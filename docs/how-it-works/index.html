Under the hood

How TermFold runs Debian and AI coding agents on Android without root

Android does not want you to run a Linux system inside an app. Five restrictions got in the way, and each one has a specific, slightly odd fix. These are the notes we wish we had on day one.

TermFold is an Android app that unpacks a real Debian 13 root filesystem and runs it with PRoot, so you can use apt, git, Node, Python and the AI coding agents (Claude Code, Codex, Gemini CLI, OpenCode and others) on a tablet. PRoot does the heavy lifting, but PRoot alone does not get you a working system. Here is what else it took.

1You can only execute files the OS installed

Since Android 10, an app cannot execve anything under its own data directory, whatever the permission bits say. There is exactly one exception: the native library directory, which the system fills at install time from jniLibs, and only for files named lib*.so.

So PRoot, its loader, libtalloc and libandroid-shmem all ship as lib*.so and are run under those names. There is no friendlier filename to copy them to, because nowhere friendlier is executable. Renaming libtalloc.so.2 to libtalloc.so breaks PRoot's DT_NEEDED entry, so the build rewrites that string in place (it only gets shorter, so no ELF offset moves). And useLegacyPackaging has to be on, or the libraries stay compressed inside the APK and execve fails even though dlopen would have worked.

2The target SDK has to be 28

At API 29 and above the app process runs in the untrusted_app domain, where executing files from app data is denied outright. Termux pins targetSdk = 28 for exactly this reason, and so does TermFold. It is the reason the app is not on Google Play, which no longer accepts such a low target.

This is not a workaround you can trade away later. Raising the target SDK breaks the Linux environment entirely.

3Raw fork() is answered with ENOSYS

Android's seccomp filter makes the plain fork syscall fail for app processes. Apps are expected to use clone. That does not stop PRoot: glibc programs use clone, so the whole Debian guest runs fine. What breaks is anything that calls fork directly, and BusyBox's tar does. The telltale sign in PRoot's verbose log is a fork that returns a child pid, then a SIGSYS that overwrites the successful result with -ENOSYS.

The fix is to not shell out at all. TermFold unpacks the root filesystem with its own tar reader written in Kotlin, which also means the filesystem is in place before any bundled executable has to prove it runs.

4Hard links are forbidden, and dpkg needs them

Inside an app's directory, link(2) returns EPERM. dpkg, npm, git, pip and tar all assume they can make hard links. The usual workaround, PRoot's --link2symlink, fakes a hard link with a hidden data file kept beside the first name. It works until a program replaces that folder, which npm does on every install: the data disappears while other names still point at it. A 240 MB Claude Code binary was lost exactly that way.

TermFold instead preloads a tiny library, through /etc/ld.so.preload, the way a distribution would. When the kernel refuses a link(), the library turns it into an independent copy of the file. Every tool above accepts that; only st_nlink stays 1. Only glibc reads that preload file, so static and musl programs are untouched.

Debian added one more wrinkle. Packages such as openssh-client run groupadd in their post-install script, and shadow's lock for /etc/group uses a hard link and then insists the link count is exactly two. No copy can satisfy that, so the setup swaps in small replacements for groupadd and useradd (with dpkg-divert, so package updates leave them alone).

5Android hides /proc/stat

Apps cannot read /proc/stat, /proc/uptime, /proc/version and a few more. Most programs shrug, but some need them: LibreOffice refuses to start without /proc/version, and the new native Codex CLI works out a process's start time from the boot time in /proc/stat so it can record its background server. Without it, Codex stops with "failed to read start time for pid-managed app server".

PRoot can bind a file over any path, so TermFold writes plausible stand-ins for the hidden files and binds them in. The one subtle part is the boot time. A process's start time is that boot time plus a per-process offset, and a program that saved it earlier compares it with what it reads later. If the fake boot time drifted by one second between sessions, the program would conclude its own process had gone. So the value is kept steady across sessions.

+Making an agent's browser cheap

TermFold also gives agents a real browser to test web work. The first version returned every control on the page on every call, which costs a lot of tokens on a long page. The current one follows what other agent browsers do: a short list of what is on screen, a --changed mode that prints only what differs from the last snapshot, --find to locate one control anywhere, and the full list saved to a file the agent can grep. On a long Wikipedia article that took a snapshot from about 29,000 characters to about 1,200. Screenshots became small JPEGs that can be skipped when the page has not changed.
